# Implementation Plan

## Approach
Three controls on one shared foundation, built in slices so every slice leaves the suite green and the existing tests unedited (REQ-023, AC-051). Ruby standard library only; no new gem, no network, no deployed service.

Design decisions the specification left to planning (each recorded so implementation does not re-open them):

- **Lock** (`lib/soft_foundry/record_lock.rb`, new): `RecordLock.synchronize(root, slug, timeout: 10) { ... }` takes an exclusive `flock` on `.soft-foundry/locks/<slug>.lock` (`.soft-foundry/` is already git-ignored, so the lock never shows in `git status` or a scope claim). The file is opened `O_CREAT|O_RDWR|O_NOFOLLOW`; a symlink or non-regular file is refused through the `SafeWrite` helpers. Acquisition polls `LOCK_EX|LOCK_NB` every 50 ms up to 10 s, then raises `TargetError` naming the lock path and "another soft-foundry command holds it; wait for it to finish". `flock` is released by the kernel on process death, so a killed run never leaves a stale lock (answers THREAT-008). Reentrant within one process via a thread-local depth counter.
- **Atomic record writes** (`ChangeRecord`): new `update_metadata { |meta| }` and `update_handoff(phase) { |h| }` helpers that take the lock, **re-read from disk** (never the cached `@record.metadata`, which is what makes `begin!`/`finish!` lose updates today), yield, and write through `SafeWrite.write` (temp + `O_EXCL|O_NOFOLLOW` + rename). `PhaseRunner#begin!`/`finish!`/`stamp_handoff` are rewritten on top of them. A multi-file `transaction` variant stages every new file as `<path>.soft-foundry-tmp`, and renames only after all staged writes succeeded, `metadata.yml` first (a crash then leaves a history entry naming a reset that is incomplete, which is visible, rather than a reset with no trace); a staging failure removes the temp files and leaves the record byte-identical (AC-017).
- **Session marker**: `SOFT_FOUNDRY_PHASE=<phase id>`, set by the runner in every session it starts (single, parallel, and panel members), plus `SOFT_FOUNDRY_PARALLEL=1` in a parallel run. `SOFT_FOUNDRY_` is a reserved prefix `--env` refuses (REQ-011). Marker present means "inside a phase session": `phase reopen`, `change release`, `change discharge` refuse (REQ-007, REQ-018, MIT-001).
- **Guard marker handling** (`guard.rb#active`): before `current_phase`, read `SOFT_FOUNDRY_PHASE`. Unset: today's path, unchanged. Set: it must match `\A[a-z_]+\z`, name a lifecycle phase (exact, case-sensitive), and when `SOFT_FOUNDRY_PARALLEL=1` be in `isolated_phases` read from `workflow.yml`; otherwise `decide` returns a violation handled per `enforcement.yml` (never a silent fallback, MIT-002). The marker's phase supplies the skill; the status check (`closed`, `judged`, and now `released`) still comes first.
- **`isolated_phases`** lives in `.ai/workflow.yml` beside `panel_phases`; `ControlPlane#isolated_phases` mirrors `panel_phases`. `check` lints it (lifecycle phases only; never implement, remediate, review, judge, or a phase whose skill's `write` set includes `${APP}`) (REQ-009). An adopter workflow without the key is valid; `--parallel` then refuses ("no isolated_phases declared").
- **History key**: `phase_reopenings` (REQ-004). `release` block shape per REQ-017. `reopenings` is untouched.
- **Release/close interplay**: judgment `undischarged` items are copied into `release.items` under their own ids (flagged `from: judgment`). When `change close` runs on a released record it passes the carried items the person discharged through `change discharge` to the existing judgment-discharge path (`ChangeRecord#discharge!`) as confirmed, so there is one owed list and no second `--confirm` prompt. Implementation must read `cli.rb` `change_close` (l.457-503) first and record any deviation in `05-implementation/deviations.md`.
- **Free-text validation** (one helper, `Text.free_text!(value, label, max: 500)`, in `lib/soft_foundry/text.rb`): non-empty after strip, at most 500 characters, no control characters (`\p{Cntrl}`, including newline, ESC, NUL), else `ArgumentError`. Used for `--reason`, release item descriptions, discharge `--note`. Ids: `\A[A-Z0-9][A-Z0-9-]*\z`, env names `\A[A-Z_][A-Z0-9_]*\z` and not `SOFT_FOUNDRY_*`. All record text goes through the YAML emitter, never string building (MIT-005). Output quotes user text via `inspect`-style quoting behind a fixed prefix.

## Implementation sequence
Each step: write the failing tests named in `testing.md` first, run to see RED, implement to GREEN, run the full suite with provider keys unset (`env -u ANTHROPIC_API_KEY -u OPENAI_API_KEY ... rake test`), commit.

1. **Foundations** — `RecordLock`, `ChangeRecord#update_metadata/update_handoff/transaction`, `Text.free_text!`, `ChangeRecord#released?`/`finished?` (closed or released) and `release_items`/`open_release_items`. Rewrite `PhaseRunner#begin!/finish!` on the helpers with no behaviour change (existing `phase_runner_test.rb` stays green). Covers AC-028, AC-029, AC-017 groundwork.
2. **Phase reopen** — `ControlPlane#downstream(phase)` (lifecycle successors plus `transitions` targets to a fixed point); new `lib/soft_foundry/phase_reopen.rb` (`PhaseReopen#call(phase, reason:, source:, commit:)`: validate status/reason/marker, compute reset set, skip pending, refuse "nothing to reset", build handoff resets and one `phase_reopenings` entry, apply via `transaction`, set `current_phase` and `judged -> in_progress`). CLI: `phase reopen <phase> --reason TEXT [--change SLUG]`, dispatch beside `run` in `Cli#phase`, usage text, exit codes (`EXIT_TARGET` for refusals). Output prefix `phase reopen:` one fact per line (`reopened <phase> (manual)`, `reset <id>` per line). Covers AC-001..AC-017, AC-046/047 for these lines.
3. **Auto-reopen in `phase run`** — `PhaseRunner#refusal(phase, allow_stale: false)`; with `allow_stale: true` a complete-and-stale phase passes the "already complete" refusal only (every other refusal still applies first, and nothing is written before all refusals are evaluated, AC-008/009). `Cli#phase` then calls `PhaseReopen` with `source: auto` and a reason naming the failed "evidence current" check and the stale `commit_sha`, prints `phase reopen: reopened <phase> (automatic: evidence stale at <sha7>)`, and runs the phase. `--dry-run` prints `would reopen` and writes nothing. Covers AC-007..AC-009.
4. **Control-plane declaration and guard marker** — `isolated_phases` in `.ai/workflow.yml`, `ControlPlane#isolated_phases`, `check` lint; runner sets the marker env (new `env` member on `PhaseRunner::Launch`, default `{}`, `inspect` redacted to variable names); `Guard#active/decide` marker resolution and violation; `spawn_shell(launch)` passes `launch.env`. Single-phase behaviour with no marker is byte-for-byte as before (AC-027). Covers AC-018, AC-025, AC-026, AC-013 marker refusal.
5. **Parallel run** — `Cli#phase run <phase> <phase>... --parallel [--env NAME=VALUE]...`: parse (repeatable `--env`, `options`), pre-flight everything before any write (`isolated_phases` membership, duplicates, plane.phase exact match, per-phase `refusal` where a named predecessor counts as satisfied if *its* predecessor is complete, env name validation), warn line when no `--env`, auto-reopen of stale named phases in lifecycle order reopening only those still complete-and-stale (reopening evaluate already resets attack as downstream, so attack is not reopened again, which would otherwise hit "nothing to reset"), then record the start HEAD and `begin!` every phase under the lock, spawn all children (`Process.spawn` with `launch.env` merged into the environment hash, never argv), a mutex-guarded waiter per child, INT/TERM trap forwarding TERM to every pid, per-child failure (including `Shell.resolve` raising) failing only that phase, `finish!` per phase under the lock, then in lifecycle order gate results and `phase <id>: pass|fail` (pass = exit 0 and gate not failed), `parallel:` summary line, HEAD-moved `warn:` and non-zero exit, `current_phase` set to the first lifecycle phase not complete. `PhaseRunner#prompt(phase, parallel_head: nil)` appends the "commit_sha is <HEAD>; do not commit" instruction. Covers AC-019..AC-024, AC-028..AC-034.
6. **Released state** — `ChangeRecord#release!` and `#discharge_release_item!` (via `transaction`), CLI `change release --item ID=DESC...`, `change discharge ID --note TEXT`, `change close` branch for released records, `ci` branch (`released: <slug>: N open item(s): ID, ID` plus advisory; zero open fails with "run `soft-foundry change close`"), `ChangeIndex#merged_unclosed?` returning false for released-with-open-items and true for released-with-none-open or malformed release block; refusals inside a session marker. Covers AC-035..AC-043.
7. **Consumers of `closed`** — each makes the decision REQ-021 lists: `scope.rb` (`finished?` claims nothing), `check.rb` (l.153 skip, plus release-block lint: missing/empty/malformed `release` on a released record fails, duplicate ids, undischarged ids absent), `snapshot.rb` (`summary`, `board_row`, timeline events for `phase_reopenings` distinct from "reopened for exploring", release and discharge events), `processes.rb` (l.267 and the `SUBCOMMANDS` table: `phase reopen`, `change release`, `change discharge`), `learning.rb`/`cli.rb` learn-promote refusal (released counts as finished), `guard.rb`/`phase_runner.rb` status lists, `change reopen` refusal text for released, `ui/server.rb` and `ui/assets/app.js` (released section with the text "released" and an open-item count, open items in a table with header cells, record text only via `textContent` through the existing `el()` helper so it stays escaped). Covers AC-044, AC-048, AC-049.
8. **Control plane, harness evals, docs** — `.ai/templates/change/metadata.yml` (`phase_reopenings: []`), `.ai/schemas.md` (status vocabulary, `phase_reopenings`, `release`, marker variable), `.ai/README.md` (isolated_phases, commands), `harness_eval.rb` `STATUSES` plus new gate cases (malformed release block; non-isolated parallel request) and a live case for stale auto-reopen following the existing case format, usage text, `README.md`, `docs/user/` (reopen, parallel with the adopter-isolation responsibility and the `--env` exposure note, released, the session-marker residual: a guard against accident, not a sandbox). Covers AC-045, AC-050.
9. **Full verification** — whole suite with provider keys unset, `soft-foundry check`, `soft-foundry eval`, a timing check for AC-034, and a hand run of every command against a scratch record.

## Application changes
As above. No existing public behaviour changes: the only altered code paths for existing inputs are `begin!/finish!` (now locked and atomic, same bytes), `PhaseRunner#refusal` (new keyword defaulting to today's behaviour), and `merged_unclosed?` (identical for non-released statuses).

## Database changes
N/A. No database exists in this repository. The per-run value `--env` passes (for example a `DATABASE_URL`) is the adopter's resource, never created or validated here.

## Infrastructure changes
N/A. No IaC, deployed service, or listener. GitHub Actions already runs `check`, `ci`, and the suite.

## Observability
Not a service (`surfaces.observability: false`). Observability is the record and the output (REQ-026): `phase_reopenings`, `release` items with discharge times and notes, snapshot timeline entries, `change status` and `ci` listing open items, auto-reopens labelled automatic. No metrics, alarms, or dashboards.

## Accessibility (surfaces.accessibility: true)
CLI output follows `.ai/rules/accessibility.md`: outcome as a word, one fact per line behind the stable prefixes `phase reopen:`, `phase <id>:`, `parallel:`, `released:`, `advisory:`, `warn:`; no ANSI/glyph-only meaning (the existing `✗ fail` / `! warn` style is reused where the surrounding command already prints it, never as the only signal); no prompts. A test asserts the byte content of each new output. UI: "released" and the count as text, open items in a `<table>` with `<th scope>` headers, new styling checked against 1.4.3/1.4.11 (reuse existing tone tokens, which already pass); docs use a real heading hierarchy and descriptive links.

## Risks
| ID | Risk | Mitigation in this plan |
| --- | --- | --- |
| R-1 | Marker is an environment variable; a session can `env -u` it (THREAT-002, TM-001) | Documented residual in docs, handoff notes, and `deviations.md`; attack phase runs PAC-01; refusal described as a guard against accident |
| R-2 | Reset applied partially (crash between renames) | Stage-then-rename, metadata first, injected-failure test; residual window is one `rename` call |
| R-3 | `release` is checked once; `ci` does not re-verify a released record's judgment (TM-003) | `check` lints the block every run; `release` re-runs the gate-based preconditions; residual noted for review |
| R-4 | Existing `change close` / judgment-discharge interplay with carried items is subtle | Step 6 starts by reading `change_close`; new tests cover carry-over then close (AC-038, AC-042); deviations logged |
| R-5 | Guard marker handling changes the hot path every tool call takes | Marker unset path is untouched code; existing guard/panel/cross-CLI hook tests run unedited; new tests are in separate files |
| R-6 | Parallel children writing the same worktree file | `isolated_phases` are evaluate/attack, which write only their own `${phase dir}` per their `permissions.yml`; guard now checks each against its own skill; sessions told not to commit; HEAD compared after |
| R-7 | Threads writing `@out` interleave lines | Single mutex around output; per-phase result lines printed by the main thread after all exit |
| R-8 | harness-eval case format not read in this phase (`${HARNESS_EVALS}` denied) | Implementation reads existing cases to follow format; AC-045 pins the outcome |
| R-9 | Carried judgment ids may not match the release id pattern | Carried ids kept verbatim, validated non-empty and control-character-free only; duplicate ids refused |
