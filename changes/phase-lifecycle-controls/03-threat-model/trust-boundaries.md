# Trust Boundaries

| Boundary | Inside | Outside | Controls crossing it |
| --- | --- | --- | --- |
| TB-1 Runner / phase session | The runner process: sets the session marker, auto-reopens, writes the record under lock | A coding-shell session (an agent) running one skill, whose Bash it controls | The session marker (REQ-013) is set only by the runner; `phase reopen`, `change release`, `change discharge` refuse when it is present (REQ-007, REQ-018); the guard checks file tools against the marker's skill and Bash against deny sets only. The marker is an environment variable, so a session can unset or change it inside a command: it is a convention the runner sets, not a credential. |
| TB-2 Person / CLI arguments | The maintainer's terminal or CI invoking commands | Free text from flags: `--reason`, `--item`, `--note`, `--env` | Length cap 500, control characters refused, ids and env names pattern-checked, `SOFT_FOUNDRY_` prefix refused (REQ-007, REQ-011, REQ-017). |
| TB-3 Record on disk | `metadata.yml`, handoffs, the new `phase_reopenings` and `release` keys | Anyone with repo write access, including a phase session editing files its permissions allow | Locked atomic writes (REQ-014); `check` lints the release block (REQ-020); the gate and CI recheck structure; evidence files are never written by reopen (REQ-003). Records are tamperable by design by anyone who can commit; detection is review and CI, not prevention. |
| TB-4 Parallel sessions to each other | One session's phase directory and permissions | The sibling sessions sharing one working tree, one HEAD, and the adopter's resources | Per-session marker so the guard checks each against its own skill; shared HEAD and no-commit instruction (REQ-015); isolation of databases or ports is the adopter's job via `--env` (REQ-011), not enforced. |
| TB-5 Adopter secrets into a session | The `--env` value held by the runner | `ps`, record, output, logs, the child process environment | Values never persisted or printed, names only (REQ-012). They do reach the child environment, which the session can read and which the shell's own transcript may capture; that is accepted and documented. |
| TB-6 `main` CI / merged record | `ci` evaluating a merged change | A record that claims `released` | `ci` passes released only with open items, fails neither closed nor released, requires approving judgment at release time (REQ-018, REQ-020). Release time checks are not re-run by `ci`; see THREAT-006. |
