# Mitigations

| ID | Threats | Mitigation | Where enforced | Verified by |
| --- | --- | --- | --- | --- |
| MIT-001 | THREAT-001, THREAT-002 | Lifecycle-rewriting commands (`phase reopen`, `change release`, `change discharge`) refuse when the runner's session marker is present; the marker is set only by the runner. Documented as a guard against accident and a prompt-following agent, not a sandbox: a session that unsets it in Bash is not stopped by the tool, and the residual is stated in docs and the handoff notes. Review and the attack phase look for the command in session transcripts. | CLI command entry, REQ-007, REQ-018 | PAC-01, AC-001-series reopen/release refusal criteria |
| MIT-002 | THREAT-002, THREAT-003 | Guard resolves the active skill from the marker, treats an unknown, empty, non-isolated, or malformed marker as a violation per `enforcement.yml`, never falls back silently; marker validated against a strict pattern and the isolated list read from `workflow.yml`. | Guard, REQ-013 | PAC-02 |
| MIT-003 | THREAT-004 | `release` requires a complete APPROVED or APPROVED_WITH_RESIDUAL_RISK judgment, at least one valid item, lifecycle end reached, gate-checked phases; carries over every judgment `undischarged` item; `ci` fails a merged record that is neither closed nor released; `check` lints the release block. | `change release`, `ci`, `check`, REQ-017, 018, 020 | PAC-03, PAC-04, PAC-05 |
| MIT-004 | THREAT-005 | Reopen only resets state, records reason, commit, previous status and session, never writes evidence or marks complete; auto-reopen is labelled and recorded; a stale phase still has to pass its gate against the new HEAD and the implementing-session-cannot-grade rule is unchanged. | Reopen implementation, REQ-003, 004, 005, 007 | PAC-11, PAC-13 |
| MIT-005 | THREAT-006 | Text inputs are capped at 500 characters, control characters (including ESC, NUL, newlines) refused, ids and env names pattern-checked; values written through a YAML emitter, never string-built; output lines use fixed prefixes and quote user text. UI and reports HTML-escape record text. | CLI validation, YAML writer, UI renderer, REQ-007, 011, 017, 025 | PAC-06, PAC-12 |
| MIT-006 | THREAT-007 | `--env` values are held only in the child environment hash; never written to the record, handoff, output, errors, or argv (so not in `ps`); names constrained and `SOFT_FOUNDRY_` refused; `{phase}` expansion applies to the value only. The child environment exposure is documented. | Runner, REQ-011, 012 | PAC-07 |
| MIT-007 | THREAT-008 | Record writes serialised under a lock with a 10 s bound, written by temp file and atomic rename, reset and history applied in one write; lock file created without following symlinks and failing with a message naming the lock when held. | Runner and commands, REQ-014, 022 | PAC-08 |
| MIT-008 | THREAT-009 | `--parallel` validates every phase against `isolated_phases` (read from the workflow, exact match, no duplicates) before starting anything; `check` fails if the list names implement, review, judge, or a code-writing phase; sessions are told not to commit, HEAD compared at the end with a `warn:` and non-zero exit. | Runner, `check`, REQ-009, 010, 015 | PAC-09, PAC-10 |
| MIT-009 | THREAT-010 | Parallel isolation of shared resources is the adopter's job; with no `--env` the runner prints a `warn:` line. Documented as accepted residual risk. | Runner output, docs, REQ-011 | PAC-10 |
