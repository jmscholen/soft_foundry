## Accepted deviations

- D2. `ControlPlane#downstream` follows lifecycle order plus `next` edges from the reopened phase and from phases reached by such an edge. Conditional edges are not followed, so reopening evaluate leaves verify complete (AC-001) and reopening remediate resets verify (AC-002). `downstream(judge)` is `[learn]`. REQ-002's "every transitions edge" reading cannot satisfy both criteria. Accepted in `architecture.md`.
- D3. See REV-003. Accepted.
- D4. A stale complete phase was already allowed by `PhaseRunner#refusal`. Auto-reopen runs after the other refusals. AC-008 and AC-009 hold.
- D5. Parallel preflight refuses `--panel`, `--max-rounds`, and `--shell-arg`, a duplicate, a phase outside `isolated_phases`, and a missing `isolated_phases` list, and it writes nothing on those refusals. `current_phase` after the run is the first phase that is not complete and not a pending skippable phase. The runner tells each session the start HEAD and does not rewrite `commit_sha`. A session that exits 0 and leaves the handoff `in_progress` is reported `phase <id>: pass`, because the gate warns on `in_progress` and does not fail it. A single `phase run` exits 0 in that same case (schema: in_progress does not fail the gate). Not filed separately.
- D6. `--env` values remain in the shell history and in `ps` until `setproctitle` runs. Accepted. See `security.md`.
- D8. `ci` on an unmerged released record with no open items prints a notice and passes. REQ-020 and AC-040 speak about a merged change. The merged case still fails and names `change close`. The `ci` line is indented under the change heading (`  released:`), so a search anchored at column 0 misses it. The words AC-040 names are present. Not filed separately (evaluation EVAL-F3).

`change close --force` skips the open-item check and the merge check. It does not skip the judgment undischarged list. A carried item counts as confirmed only when `discharged?` is true (IMPL-004). That holds, including for the U+00A0 case in REV-009.
