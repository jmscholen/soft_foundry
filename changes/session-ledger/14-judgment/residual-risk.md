## Not carried as residual risk (accounted for, not defects)
- FIND-ATK-001. A hook payload over 1 MB is not recorded; the session is recorded at its next ordinary prompt. Fail-safe (MIT-005). README states it. Review did not reopen it.
- FIND-ATK-002. Control characters are removed from a folder name, so that session reports `folder missing`. Safe direction. README states it.
- EVAL-OBS-002. A Grok hook payload carries no transcript path, so status checks only the folder. The specification records the transcript when the agent sends one. Not a miss.
- EVAL-OBS-003. The list item's computed accessible name is fragmentary because its parts are child nodes. Review read that as the children being exposed, not a failure. Not reopened.
- EVAL-OBS-001 and REM-001. The resume command sat on the same line as the prompt, and `grok -p` was given its prompt in the wrong position. Both fixed at `93acd89` and re-checked. `phase_runner.rb` builds `["-s", id, *extra, "-p", prompt]`. `app.js` puts the command on its own line as text.
- DISC-001. The page's existing "sessions" wording meant open shells. The recorded list is labelled "Recorded sessions".
- Masking covers the six secret shapes the content scan names, and nothing else. That is the specified mask. Credentials that match none of those shapes can still be stored. The ledger is not pruned; README says to delete the file. Hook failures after install are silent by REQ-SL-005. Characters outside C0, C1, and DEL are not stripped; MIT-003 does not require it.
- `10-user-documentation`, `11-faq-index`, and `12-observability` pending. Optional phases, not started. User-facing text is in README and help (AC-015). No deployed service, so no production dashboard is owed.
- Verification, evaluation, and attack were run by the session that implemented the change. Review and this judgment were fresh sessions. The logs, RED commits, and the independent code read are what this outcome relies on. The shared session is a process limit for learning, not a product defect.
