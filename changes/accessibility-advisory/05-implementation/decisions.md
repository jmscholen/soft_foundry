# Implementation Decisions

| Decision | Alternatives considered | Reason | Consequence |
| --- | --- | --- | --- |
| Advisories are a separate class (`Advisory`) with its own output block, not extra `Gate` checks with a `:warn` outcome | Add warn-level checks to each phase's gate result | A gate result is per phase and its checks answer "is this phase's evidence complete"; advisories are per change and answer "what should a human know before shipping". Mixing them would make `warn` lines show up under a phase that did not cause them, and pending phases return only a skip check today | One heading, one prefix (`! warn <area>:`), printed after all gate results and on close; exit codes untouched |
| Word next to glyph (`✓ pass`) rather than word instead of glyph | Replace glyphs with words; keep glyphs only | Sighted users scanning a terminal benefit from the glyph; screen readers, CI logs, and fonts without the glyph need the word. Both cost nothing | Every outcome line is one token longer; the standard records the rule so future output follows it |
| `change new` edits the `accessibility:` line as text | Load YAML, set the key, dump | `YAML.dump` drops the template's comments, which are the only documentation an agent sees in the record | The line's own comment is replaced with who set it and why; a test asserts the other comments survive |
| The UI-framework list is `Advisory::UI_FRAMEWORKS`, the same names the maturity scan detects | Read the list from a policy file | The scan is the only thing that writes `technology.frameworks`, so the names are already fixed; a second list would drift | Extending scan detection means extending this list in the same change |
| `check` warns rather than errors on a missing standard; scan scores absence as UNKNOWN | Error; MISSING | The maintainer asked for reporting. A standard may live somewhere the scan does not look, and the plane still functions without the file | An installed plane that deleted the file keeps passing `check` and `ci`, but every `check` run says so |
| `ci` prints advisories only for open records | Print for closed records too | `ci` already skips closed records to avoid stale-evidence noise; their go-live moment has passed and `close` printed the advisories then | The seven historical records that skipped review do not show up on every `ci` run; they are visible through `gate all --change <slug>` |
| Review and judge skips are advised regardless of the accessibility flag | Only when the flag is true | Skipping independent review removes the security and standards checks too, not only accessibility; the maintainer wants to know before go-live | This change's own gate output carries a judgment advisory, by design |
