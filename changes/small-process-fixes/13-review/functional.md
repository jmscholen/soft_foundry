## Conformance

The five features are present and match the acceptance criteria on the paths the tests and the evaluation ran.

- REQ-001, AC-001, AC-002. `--type` and `--risk` are written by a text edit that keeps the template comments. Omitting a flag leaves the template placeholder.
- REQ-002, AC-003. A spaced value outside the vocabulary is refused before `scaffold`, and the message names the flag, the value, and the list. REV-002 is the equals-form and repeated-flag hole.
- REQ-003, AC-004. One constant is the vocabulary. `check` fails when the template comment disagrees, and when `waivable_by_risk` keys disagree. `--risk high` with `--track iterative` is refused. REV-006 is the unlinted `forced_by_risk` key.
- REQ-004, REQ-005, REQ-006, AC-005 through AC-008. For an Array, single runs, the auto-reopen path (it uses the single-run return), and parallel runs set `status: blocked`, keep `blocking`, append the runner sentence to `notes`, and print `blocked:`. A failed `update_handoff` prints `warn:` and leaves the file. A hand-edited `complete` handoff with blocking items still fails the gate. REV-001 is the parallel process status. REV-003 is a non-Array `blocking` value.
- REQ-007, AC-009. The adversarial-testing, verification, and review skills and the README content-scan section tell agents to write invisible and control characters as visible escapes or as source escapes. `content_scan.rb` is unchanged. Landed in `cf932d1` after the implementation phase recorded that it could not write `.ai/` or the README.
- REQ-008, REQ-009, REQ-017, AC-010, AC-011, AC-019. `change summary` prints the stable prefixes, refuses an unknown slug with the known names, reports an unreadable or oversized or alias-using handoff as `unreadable` and continues with exit 0, and does not construct `Gate`. Advisory lines are computed from the record; they are part of `owed:` in the specification. The evaluation empty-record run finished well under a second.
- REQ-011 through REQ-014, AC-013 through AC-016. The rule file, the optional `tests.yml` fields, and the verification-only `protection stated` check match the specification. No `access_control`, or no matching path, skips the check. An unclosed `[` or `{` fails it. Older records without the fields stay valid when the check does not apply.
- REQ-015, AC-017. No new network call, credential, or privilege. `mark_blocked!` writes only the handoff of the phase argument, through the record lock.
- REQ-016, AC-018. `blocked:`, the summary prefixes, and the `protection stated` result are plain text lines. REV-001 means a parallel blocked run does not show up in the process status.
- REQ-018, AC-020. Covered in `policy-conformance.md`.

`phase run --panel` does not call `mark_blocked`. REQ-005 names single runs, parallel runs, and auto-reopened runs. The panel path is outside that list.
