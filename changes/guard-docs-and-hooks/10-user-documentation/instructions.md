## Who can use it
- **Maintainer of a repository** running `soft-foundry hooks install`, `doctor`, `guard --after`, and `eval --live`, and overriding the mode on their own machine. No authorization boundary beyond the machine's own file permissions: the override and the environment variable are the maintainer's, outside any guarded session.
- **Agent session** on a change branch, whose tool calls the hook decides according to the active skill's `permissions.yml`. The session cannot change the mode or the hook from inside; it can read the configuration and the log with the Read tool.
- **Reader** of the README guard section and of `docs/user/guard-hook.md`, including through a screen reader or a CI log: every outcome is a word (`pass`, `fail`, `warn`, `installed`, `removed`, `block`), no ANSI escape reaches a pipe, no route prompts (EVAL-009).

## Steps
Written for a person, in `docs/user/guard-hook.md` and the README's "Runtime enforcement: the guard hook" section. In short:

1. **Install or update the hook.** `soft-foundry hooks install --claude` (`--local` for this machine only; `--codex` for Codex, then `/hooks` inside Codex). Read the two `installed ...` lines and the `guard mode:` line. Run `soft-foundry doctor` and read the `guard hook` line. A repository that installed the hook before 0.21.0 runs the same command again; nothing else is needed.
2. **Change the mode on one machine.** Write `.soft-foundry/enforcement.yml` with `guard: { mode: "off" }` (quoted) or set `SOFT_FOUNDRY_GUARD`. `doctor` names the source in effect.
3. **Edit the configuration by hand after an interrupted shell command.** Run `soft-foundry guard --after` once (quiet when nothing changed, consumes the baseline), or rerun `hooks install`; then edit.
4. **Read a refusal.** Match the message to the table in `docs/user/guard-hook.md`; every message names the tool, the path, the skill, the mode and where the override is documented; the same decision is one line in `.soft-foundry/guard.log`, readable with the Read tool.
5. **Run a live harness eval unattended on Claude Code.** Pass the shell flags after `--` as in the README's harness-evals section.

## Troubleshooting
Only behaviour supported by successful evaluation.

- **Grep or Glob reach a denied directory, or a changed `.ai/policies/enforcement.yml` is not restored after a shell command.** The repository's hook predates 0.21.0. Rerun `soft-foundry hooks install --claude`; `doctor` still said `installed` before the rerun, because it reports presence, not the matcher (EVAL-003 `hooks-upgrade.txt`, `doctor before the rerun`).
- **`mode: off` in the override has no effect.** Quote it: `mode: "off"` (EVAL-005 `yaml-off.txt`).
- **`Bash could not be decided (NoMethodError: undefined method 'empty?' for nil)`.** The command leaves the repository with `cd` or `pushd` and has another token, typically a redirection, in the same segment. Drop the redirection or put it elsewhere: `cd /tmp && ls` is decided (EVAL-004 `glob-outside.txt`).
- **A shell `cat` or `tail` of the hook settings, the policy, or the guard log is refused although the Read tool reads the same file.** That is by design: the guard's own configuration, including everything under `.soft-foundry/`, may not be named from the shell by any skill; Read is checked against deny_read only (EVAL-001 `guard-live.txt`, EVAL-004).
- **A shell command naming `.ai/policies/<file>` is refused although the file does not exist.** Protected policy is refused by name, existing or not (EVAL-001 item 2).
- **My hand edit of the configuration was restored and reported as tamper.** A shell command was interrupted before its check within the last thirty minutes. Run `soft-foundry guard --after` once, or rerun `hooks install`, then edit (EVAL-004: baseline consumed by the check, quiet with nothing to restore, stale baseline refreshed, cleared by `hooks install`; factory-readiness EVAL-F7 closed).
- **An Edit failed with "String to replace not found" and the guard log has no line for it.** Claude Code validated the Edit before the hook ran; nothing was written (EVAL-001, EVAL-F-006).
- **`eval --live --shell claude` fails with `0 findings recorded`.** The session could not write the phase directory. Pass `-- --allowedTools "Read Write Edit Glob Grep Bash" --permission-mode acceptEdits` (factory-readiness EVAL-004 run 2).
