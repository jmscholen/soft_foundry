# Assumptions

## Explicit assumptions
- The maintainer's rationale is applied as stated. Noted for the record, without changing the decision: a security policy in the sense the standard uses (a vulnerability disclosure route for the software itself) is about the tool's own defects, not about user data, so the rationale given is closer to the privacy argument already recorded. The maintainer owns the call and it is recorded verbatim.
- Recording NOT_APPLICABLE with a dated rationale, rather than deleting the `security` entry, keeps the standard's rule that absence is stated, never silent.

## Ambiguities resolved
- Whether a one-line evidence edit needs a change record: yes. `.ai/` edits are the category most often committed straight to main as housekeeping, and the maintainer's standing preference is that every control-plane edit goes through its own record.

## Ambiguities that block safe progress
None.
