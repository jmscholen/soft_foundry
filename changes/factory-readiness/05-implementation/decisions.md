# Implementation Decisions

| Decision | Alternatives considered | Reason | Consequence |
| --- | --- | --- | --- |
| One `SoftFoundry.read_text` helper (`binread`, force UTF-8, `scrub`) in its own file, required by each module that reads text | Set `Encoding.default_external` in `exe/soft-foundry`; pass `encoding:` at every call | A process-wide default is not set when the library is required by a test or another program, and would change what the host's own code sees; a helper is explicit and testable | Every content read in `lib/` goes through one line; binary reads (`File.binread`) stay as they were |
| The gated-track lock is the commit that recorded the completed specify handoff, found by `git log -1` on the handoff and checking `status: complete` in that blob | The specify handoff's `commit_sha` | `commit_sha` is HEAD when the outputs were produced, which precedes the commit that holds them, so comparing against it always reports the outputs as changed | A specification that is complete but uncommitted warns `not yet locked` rather than failing; the lock takes effect at the commit |
| Downstream staleness on a specification change compares the order of two recorded commits (lock vs. the phase's own recorded commit) by ancestry | Compare `02-specification/` content between the two commits; compare against the phase's `commit_sha` | Record files written after a phase's `commit_sha` are the norm, so a content comparison against `commit_sha` would stale everything; ancestry of the handoff commits says exactly "re-recorded after" | Recorded in the same commit is current; a re-stamped specification committed later stales every phase recorded before it (MIT-005); an uncommitted re-stamp is caught by the lock check instead |
| `waivable_by_risk` is a workflow key, read case-insensitively, with review and judge hard-coded as never waivable in `ControlPlane::NEVER_WAIVED` and refused by `check` | Risk-specific required-phase lists per track; a policy file | The lifecycle is the workflow's; the never-waived pair is the rule `final_judgment_required` already states, so it is code, not configuration someone could edit away | Predecessor stepping (`effective_predecessor`) is unchanged: a waived phase still steps; the `waivers permitted` check is what fails the record |
| `change close` refuses on judgment status, before the merged check, with the exact `--force` wording | Only `reached_lifecycle_end?` | The person should be told the real reason (no judgment) rather than "has not reached the end of its lifecycle" | `reached_lifecycle_end?` also never treats judge as a waived end, so `ci`'s merged-unclosed check does not flag such a record as finished |
| `Guard::SELF_PROTECTED` is a flat list of five paths checked for write tools and for shell mentions, in every skill, before the skill's sets | Add them to every skill's `deny_write`; a path group | Permissions are the skill's; the guard's own configuration is not any skill's business, and a list in the guard cannot be narrowed by a permissions edit | The review skill, which may touch nothing in `.ai/` anyway, now refuses `.claude/settings.json` too; the refusal line names "the guard's own configuration" |
| The block-mode refusal says a machine-local override is documented, not what to set | Name the file and the value | A steered session reading the refusal should not be handed the way round it (THREAT-001) | The README still documents the override fully for the maintainer |
| The eval runner reuses `ChangeRecord.create`, `Gate`, and `CLI` (`phase run` in-process with `root:` and `runner:`) in a scratch git repository | A separate fixture format; shelling out to `soft-foundry` | Whatever the suite proves and whatever an application repository proves is then the same code path, and an installed gem needs no test helper | The live run's output is captured, not shown; the shell's own output goes to the terminal as `phase run` does |
| Tokens (`${COMMIT}`, `${APP_FILE}`, canaries, the invisible character) are substituted into file contents by the runner | Literal values in case files | The commit is unknowable in advance; the app file depends on the host's `APP` group; a secret shape or an invisible character in a case file would be refused by the control-plane scan | Case files carry nothing the scan refuses and work in a Rails repository where `APP` is `app/**` |
| The scratch repository drops `.ai/harness-evals/` and gets its own `AGENTS.md`, app file, and test file | Copy everything | The cases are not part of what is being tested, and a planted code change must be in a path group the gate watches | `${APP_FILE}` resolves to `lib/eval_app.rb` here and `app/eval_app.rb` in a Rails repository |
| The eval cases ship with the control plane (`Installer::Source` includes `cases/`) | Keep them this repository's own, as the earlier exclusion intended | REQ-FR-005: an application repository proves its installed gate with one command | `test/installer_source_test.rb` and `test/cli_init_test.rb` assert the new rule |
| `eval --json` carries `version: 1, stable: false` | A stable contract now | The same stance as `change status --json` | Consumers are told the shape may change |
| Three existing tests that asserted superseded behaviour were rewritten rather than deleted | Delete them | `.ai/rules/testing.md` allows rewriting an expectation under an approved requirement change, and these are REQ-FR-002, REQ-FR-004, and REQ-FR-007; each rewritten test says which | `test_the_gated_track_locks_the_specification_at_the_commit_that_recorded_it`, `test_close_refuses_a_lightweight_change_that_waived_judgment_unless_forced`, `test_guard_command_warns_and_allows_in_warn_mode_and_logs_the_violation` |
