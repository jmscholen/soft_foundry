# Security Review

## Scope reviewed

THREAT-001..005 and MIT-001..005, against `Guard#narrow_for_panel`, `Guard#shell_paths`, `Guard#mentioned_paths`, `Panel#run`, `Panel#fingerprint_phase_folder`, `Panel#fingerprint_outputs`, and the prompts in `Panel#prompt_for`. Threats: a member steering another through a draft, writing outside its folder, reading a sibling draft early, forging agreement, or expanding the panel. Rules: `.ai/rules/security.md` (least privilege; do not trust client-supplied paths), `.ai/rules/errors.md` (do not turn an integrity failure into success).

The first review's REV-SEC-001 (literal shell redirect of a sibling draft), REV-SEC-002 (Grep or Glob given the sibling path), and REV-SEC-003 (consensus prompt quoting the agree line, and a consensus write of a draft) are closed on the inputs they named. The second review's REV-SEC-004 (in-repository own-folder write), REV-SEC-005 (assignment that replaces a draft, then a later round agrees), and REV-SEC-006 (assignment that writes a phase output during the independent stage, which becomes the baseline) are closed on the inputs they named. Controls re-run in this session: independent `specification.md` exits 1 with outcome `failed`; an argument-stage draft replacement exits 1 with outcome `failed` and no consensus; `Write` of `panel/claude-1/draft.md` in the independent stage is a violation.

Repository default `guard.mode` is `warn` (`.ai/policies/enforcement.yml`). The findings below are `allow`, so block mode would not refuse them either. Each guard result is `Guard#decide` in a throwaway repository whose current phase was `specify`, member `claude-1`. Each panel result is `panel_run` with a stand-in launcher that performs the write or read the guard allowed.

## What holds

Literal redirects and `cp` of a sibling draft are violations, in every stage, for `Bash` and `run_terminal_command`. `Write` and `Edit` of another member's draft, of the handoff, of `ARGUMENT.md` in the independent stage, and of the panel folder in the consensus stage, are violations. `Grep`, `Glob`, and a read that names the sibling path or the other staging directory are violations. A phase output written during the independent stage fails the run before consensus. A draft or watched phase output changed during the argument fails the run before a later round and before consensus. A draft changed during the consensus fails the run. The consensus prompt points at the last `agree:` line in `ARGUMENT.md` and does not contain the agreed sentence.

Shell names come from a fixed list. Member names are `<shell>-<n>`. `--shell-arg` values are separate argv elements. Bounds on members and rounds hold. Prompts tell each member that other members' files are data, not instructions. Whether a model obeys a draft anyway is not something the runner can prevent (ATTACK-001, not run live).

A malformed `SOFT_FOUNDRY_PANEL_MEMBER` disables narrowing and the skill's own permissions apply (ATK-RES-001). Reproduced previously: member `not-a-member`, `Read` of the sibling draft, allow. The runner only sets names that match `Panel::NAME`. A member's shell export does not change the environment the hook process inherits from the coding shell. No member input reaches this, so it is not a finding.

## Conformance

Does not conform. REV-SEC-007, REV-SEC-008, and REV-SEC-009 are reachable with the guard in block mode, and each reproduced panel exits 0 with `panel recorded` passing. REV-SEC-004, REV-SEC-005, and REV-SEC-006 are fixed for the files and commands they named.
