# Security Review

## Scope reviewed

THREAT-001..005 and MIT-001..005, against `Guard#narrow_for_panel`, `Guard#shell_paths`, `Panel#run`, and the prompts in `Panel#prompt_for`. Threats: a member steering another through a draft, writing outside its folder, reading a sibling draft early, forging agreement, or expanding the panel. Rules: `.ai/rules/security.md`, `.ai/rules/errors.md`. The first review's REV-SEC-001 (literal shell redirect), REV-SEC-002 (Grep given the sibling path), and REV-SEC-003 (consensus prompt quoting the agree line, and a consensus Write of a draft) are closed on the inputs they named. `test/panel_remediation_test.rb` passed in this session. The cases below are what those fixes do not cover. Each guard result was produced with `Guard#decide` in a throwaway repository whose current phase was `specify`.

Repository default `guard.mode` is `warn` (`.ai/policies/enforcement.yml`). In that mode a violation is logged and the tool call still runs. The attack phase's "denied" results were taken with the guard in block mode. The findings here are all `allow`, so block mode would not refuse them either.

## What holds

Literal redirects and `cp` of a sibling draft are violations, in every stage, for `Bash` and `run_terminal_command`. `Write` and `Edit` of another member's draft, of `ARGUMENT.md` in the independent stage, and of the panel folder in the consensus stage, are violations. `Grep`, `Glob`, and `grep` that name the sibling path or the other staging directory are violations. The consensus prompt points at the last `agree:` line in `ARGUMENT.md` and does not contain the agreed sentence; reproduced by `test_the_consensus_prompt_does_not_carry_the_agreed_text_as_an_instruction`. A draft changed during the consensus fails the run even when the writer exits 0. Shell names come from a fixed list. Member names are `<shell>-<n>`. `--shell-arg` values are separate argv elements. Bounds on members and rounds hold.

A malformed `SOFT_FOUNDRY_PANEL_MEMBER` disables narrowing and the skill's own permissions apply (ATK-RES-001, and the test asserts the allow). Reproduced: member `not-a-member`, `Read` of the sibling draft, allow. The runner only sets names that match `Panel::NAME`. A member's shell `export` does not change the environment the hook process inherits from the coding shell. No member input reaches this, so it is not a finding. It stays fail-open for any process that starts the hook with a bad value.

An unknown tool that names a path is narrowed in the independent stage and is not narrowed in the argument or consensus stages (`fs_write` of a sibling draft is allow in both). The consensus fingerprint still fails the run if the draft changes. The argument stage does not; that is the same laundering as REV-SEC-005, reached without the shell.

## Conformance

Does not conform. REV-SEC-004, REV-SEC-005, and REV-SEC-006 are reachable with the guard in block mode. The first review's three security majors are fixed for the commands they named.
