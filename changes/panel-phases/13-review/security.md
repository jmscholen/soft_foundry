# Security Review

Reviewed at `661b454` (panel code identical to `4f3b2da`). Standards: `.ai/rules/security.md`, THREAT-001..005 and MIT-001..005 in `03-threat-model/`. The guard's shell parsing is still a heuristic. REM-003 made the runner's repository snapshot the control that is supposed to hold. These cases were run in a throwaway git repository; this checkout was not the target.

## Scope reviewed

`Panel#repository_snapshot`, `identical_drafts`, and `staging_for`; `CLI#spawn_panel` and the handoff merge in `panel_run`; `Guard.mode` and `narrow_for_panel`; the panel prompts; README lines that say the snapshot fails the run for anything else and that members are not sandboxed.

## Closed

Synchronous writes of git-visible files are caught. Reproduced: an argument-stage replace of `handoff.yml` (REV-SEC-007), of `lib/app.rb` (REV-SEC-008), and of a dotfile in the phase directory (REV-SEC-010) each exit 1 with `panel.outcome` `failed` and a `✗ fail panel:` line that names the path. Two byte-identical drafts fail before the argument (the original REV-SEC-009). A split whose consensus also writes `lib/app.rb` is `blocked` and is not `awaiting_human` (REV-FUN-006). Attack cases ATTACK-002..008 at this commit match those controls for the synchronous inputs they ran.
