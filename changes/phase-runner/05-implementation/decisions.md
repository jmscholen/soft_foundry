# Implementation Decisions

| Decision | Alternatives considered | Reason | Consequence |
| --- | --- | --- | --- |
| One phase, one fresh session, then the gate | A loop that runs phases until one fails; worktree per phase | The minimum that makes separation a process boundary; orchestration and isolation are the roadmap's larger runner | `phase run` composes with `gate` and `change status` rather than replacing them |
| Refuse before launching what the gate would refuse after | Launch and let the gate speak | A session costs tokens and time; the four refusals are the gate's own rules | `PhaseRunner#refusal` reuses `effective_predecessor` and `skippable?` |
| The prompt points at files, it does not restate them | A long prompt embedding SKILL.md and the rules | The control plane is canonical; a prompt that copies it drifts | Short prompt, five listed contract files, five numbered instructions |
| `executed_by` is written by the runner before and after, never by the agent | Ask the agent to record how it ran; a separate runs ledger | The runner is the only party that knows a fresh process was started; a field in the handoff is where the gate and advisory already look | The template carries `executed_by: null`; AGENTS.md says never to write it |
| The advisory covers review and judgment only | Every phase | Separation of duties is about who looked at the work; implementation in a fresh session is fine but not the capability | Two notices, `review` and `judgment` areas, on every gate/status/ci/close |
| A failed session leaves `in_progress` and its exit status | Reset to pending | The attempt is a fact; a rerun overwrites `executed_by` and the gate decides | `finish!` always runs, even on non-zero exit |
| Staleness is measured on the record's own branch when it exists and is not checked out | Rebind the earlier record to the stacked branch's commit; skip other branches' records in `ci` | Rebinding claims evidence covers code it never saw; skipping would also skip the PR's own record in a detached CI checkout. The record's branch is the honest measure; `origin/` is consulted so CI with every branch fetched still finds it | The merged-but-not-closed check is untouched and still forces closure on the default branch |
| Hooks prefer a checkout's `exe/soft-foundry` over the gem on PATH | Keep PATH first; tell developers to uninstall the gem | This repository's own pre-commit hook was running 0.3.0 and rejecting commits its checkout's `ci` passes; a checkout of the tool is the tool | The check is `-x exe/soft-foundry` and `-f lib/soft_foundry.rb`, so an unrelated repository with an `exe/` directory is unaffected |
| Warn, do not refuse, when the guard hook is missing | Refuse to launch | A non-Claude repository has no hook to install and the phase still has to run | One `! warn guard:` line naming the skill and the install command |
| `governance.separation_of_duties` becomes PASS | Stay PARTIAL until judgment has actually run through the runner | The capability is that the separation can be enforced and the record says whether it was; whether a given change used it is what the advisory is for | The maturity rule says exactly this; `judgment.final_gate` stays PARTIAL |
