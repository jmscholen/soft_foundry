# Implementation Decisions

| Decision | Alternatives considered | Reason | Consequence |
| --- | --- | --- | --- |
| One `guard` command reads the hook payload and answers with an exit code | A generated per-skill hook script; a long-running server | The active skill changes with the record, not with an install; one command reads the record each time and needs no regeneration | The hook command in settings is constant; `hooks install --claude` never needs rerunning when phases change |
| The mode lives in `.ai/policies/enforcement.yml` with a `.soft-foundry/` override and an environment variable | Mode in the settings file; a CLI flag on install | Policy is protected from skills; a machine must be able to run block mode without a commit; the environment is what a person reaches for mid-session | Same three-level shape as the budget warning threshold |
| Shipped default is `warn` | `block` | Day-one safety of governed repositories: a wrongly blocked call is worse than a logged one while the Bash heuristic is new | Every violation is logged so a warn-mode run leaves a trail; block is one line away |
| Bash is checked against deny sets only | Allow-list for Bash; parse the command for writes | The guard cannot know what a command writes; an allow-list would block `bundle exec rake test` (no path) or require shell semantics | Documented in the policy file, README, and AGENTS.md as a limit the agent must honour as policy |
| Read is checked against deny_read only | Enforce the read allow-list too | Read lists are advisory context; every skill's real boundary is its deny_read set | A skill reading `Gemfile` is not a violation |
| Fail closed on an unreadable payload in block mode | Fail open always | A guard defeated by malformed input is not a guard; warn mode keeps its promise not to block | Two message shapes, both with a status word |
| Writes outside the repository are violations for every skill | Allow (no path group matches) | No skill's write set names anything outside the root, so "not in write" already applies; saying "outside the repository" is clearer | One explicit reason string |
| The settings installer keeps every other key and hook and recognises its own entry by a marker in the command | Overwrite the hooks block; a separate ID field | Claude Code's settings schema rejects unknown keys on hook entries; the marker survives inside the command string | Idempotent install, exact uninstall, tested with a foreign hook present |
| The doctor line folds the mode into the `claude guard hook` check | A separate `guard mode:` line | `.ai/rules/accessibility.md`: every doctor line carries pass or fail, and `StatusWordTest` enforces it | One line, longer, still one status word |
| `governance.skill_permissions` becomes PASS | Stay PARTIAL until every machine installs the hook | The capability is declared, linted, and enforceable; per-machine installation is operational and reported by doctor | The maturity rule says so explicitly |
