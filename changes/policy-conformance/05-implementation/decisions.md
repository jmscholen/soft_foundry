# Implementation Decisions

| Decision | Alternatives considered | Reason | Consequence |
| --- | --- | --- | --- |
| The flag is `surfaces.policy` | `surfaces.personal_data` (as first sketched); `surfaces.compliance` | The standard covers security-policy promises (encryption, MFA, disclosure timelines) that are not personal data; "compliance" suggests a legal regime rather than the application's own documents | One word, and the comment beside it in the template says what it means |
| Published documents are recorded in `.ai/repository.yml` under `policies:` with PASS / MISSING / UNKNOWN / NOT_APPLICABLE | A capability per document; a list of paths only | The maturity capability is about the *standard* being in force; whether an application publishes a privacy policy is a fact about the application, and MISSING must be visible without lowering the repository's engineering maturity | A library gem can be honestly MISSING a security policy at level 5 |
| The scan records UNKNOWN when it finds no document, never MISSING | MISSING when nothing is found | `.ai/maturity.yml`'s own rule: absence must be established; a policy may live outside the repository | Only discovery (agentic) writes MISSING; the advisory treats anything but PASS as "no document to check against" |
| `change new` sets `surfaces.policy` only from a PASS document | Set it whenever a `policies:` block exists; never set it | A true flag with no document behind it would advise on every change in a repository that has recorded honest absence; mirrors accessibility's rule (a UI framework detected) | A change that should be checked in a repository with MISSING policies is advised when the author sets the flag by hand: "no published document to check against" |
| A human decision lives in `metadata.yml` `human_decisions` | The review handoff's `notes`; a file under `14-judgment` | It is not phase evidence; `status: awaiting_human` already lives in metadata per `.ai/schemas.md`, and any phase may need to read it. A `decided_by` still holding the template placeholder does not count | The advisory can distinguish "not parked yet", "parked, waiting", and "decided"; `governance.human_boundaries` now has a recording mechanism, though not yet enforcement |
| The owed-policy-change advisory fires regardless of `status` | Only when status is not `awaiting_human` | Parked is still "not live"; the person shipping needs the reminder either way, so the wording changes rather than the notice disappearing | Two messages for one condition, both starting `! warn policy:` |
| Evaluation owes nothing new; the threat model owes a trust boundary per new recipient | Require "Policy observations" in evaluation results, mirroring accessibility | Policy conformance is code read against a document (review); evaluation exercises behaviour and would only restate the review | No evaluation-shaped advisory for policy |
| `.ai/policies/human-boundaries.yml` gains an explicit line | Rely on the existing "legal commitments" entry | The gap this change closes is precisely that nothing routed a policy text change to that entry; naming it removes the argument. Policies are protected from skills' write sets, not from a maintainer change through its own record | One more line under `require_human_approval` |
| Shared `requirement_notices` for accessibility and policy | Duplicate the specification check | Same logic, different category and wording | Adding a third surface later is one call |
| `Advisory.ui_frameworks` / `Advisory.policy_documents` are class methods on the plane | Keep instance methods and build a throwaway `Advisory` inside `ChangeRecord#scaffold` | `change new` needs the answers before a record exists to construct an `Advisory` from | Instance methods delegate; `ChangeRecord` calls the class methods |
