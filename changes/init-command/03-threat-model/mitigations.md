# Mitigations

Enforcement points refer to the installer the plan will introduce (`lib/soft_foundry/installer.rb`), the existing adapters (`AgentFiles`, `Onboarding`), the CLI option parser, and `Check`. "Verified by" names an acceptance criterion from `02-specification/acceptance-criteria.yml` where one exists, otherwise a proposed test the plan should bind; proposed names are suggestions, not commitments.

## Specification gaps
These are requirements the mitigations need that `02-specification` does not state. They are listed for planning to raise; the specification is not edited by this phase.

1. **Uncommitted modifications (MIT-004, MIT-006).** The specification allows `updated` and `forced` to overwrite any file that matches the manifest or is forced, including files with uncommitted edits that git cannot restore. Proposed requirement: a managed file with uncommitted modifications in the target work tree is always `conflict` (reason `uncommitted`), even under `--force`. Under `--allow-non-git` there is no work tree, so every overwrite is unrecoverable; the specification should say that `--force` with `--allow-non-git` is refused or requires an additional explicit flag.
2. **`--force` scope (MIT-006).** The specification says `--force` "never touches files outside the managed set" but does not define whether pointer files, `.ai/repository.yml`, `changes/README.md`, `docs/user/README.md`, and `.gitignore` are inside that set. Proposed wording: `--force` applies only to `conflict` statuses on files in the packaged `.ai/` set.
3. **Internal symlinks and non-regular files (MIT-001, MIT-014).** REQ-013 rejects writes that "traverse a symlink that leaves" the root. Symlinks that stay inside the root, and FIFOs, sockets, or devices at a managed path, are unaddressed. Proposed requirement: any symlink or non-regular file at or above a managed destination is a target-side refusal.
4. **Manifest scope and deletion (MIT-005).** The specification does not say that unknown manifest entries are ignored, that the manifest is schema-validated, or that `init` never deletes. Proposed requirements: managed set equals the packaged set; unknown entries reported and ignored; `init` never removes files.
5. **Marker semantics (MIT-009).** "Present with the marker: skipped" lets a bare marker line suppress the bootstrap. Proposed requirement: `skipped` requires the full canonical block between opening and closing markers; a marker without the block is `conflict`. This also changes AC-004/AC-005 wording slightly ("marker block appended once" already implies the full block).
6. **Resolved root semantics (MIT-008).** The specification does not say whether `--root` must be a Git top-level or may be a subdirectory, does not mention `GIT_WORK_TREE`/`GIT_DIR`, and does not require the resolved root to be printed. Proposed requirements: `--root` must resolve to the top-level unless `--allow-non-git`; the report's first line names the resolved absolute root.
7. **Failure classification precision (MIT-012).** "Control-plane check fails immediately after a clean install" needs "clean" defined: no `conflict` and no pre-existing non-identical `.ai/` file. Otherwise target conditions are labeled Soft Foundry-side and the maintainer is directed to post their diagnostics upstream. The diagnostic's content rules (no env values, no absolute paths, no hostnames) should be a stated requirement under REQ-011 or REQ-013.
8. **`.gitignore` effectiveness (MIT-011).** AC-009 treats textual presence of the line as success. Proposed requirement: `skipped` for `.gitignore` requires `git check-ignore` to confirm `.soft-foundry/` is ignored; otherwise `conflict`.
9. **`repository.yml` override lint (MIT-010).** Whether emptied or removed required path groups in `repository.yml` should be a `check` warning or error is a control-plane policy decision outside this change's specification. Planning should decide and, if it is in scope, add a requirement; if not, record it as a follow-up change.
10. **Concurrency (MIT-007).** No requirement covers concurrent runs. A lock file under `.soft-foundry/` is cheap; the specification should either require it or state that concurrent runs are unsupported.
