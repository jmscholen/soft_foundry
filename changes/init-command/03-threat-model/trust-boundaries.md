# Trust Boundaries

| Boundary | Inside | Outside | Controls crossing it |
| --- | --- | --- | --- |
| Packaged gem to installer | Installer code and the canonical `.ai/`, `changes/README.md`, `docs/user/README.md`, `.ai/templates/repository.yml` shipped in the gem | RubyGems distribution, the local gem directory and its permissions, anyone who can publish or modify the gem | Content is trusted as-is; packaged relative names are validated (no `..`, no absolute components, no symlinks); managed set is enumerated from the package, never from the target; gem version recorded in `.ai/manifest.yml`; missing or unreadable package files are a Soft Foundry-side failure (exit 4) that writes nothing (MIT-002, MIT-003) |
| Installer to target repository | Planned writes under the resolved root: `.ai/**`, `.ai/manifest.yml`, `changes/README.md`, `docs/user/README.md`, `.gitignore` line, `AGENTS.md`/`CLAUDE.md` blocks | Every other path on the filesystem, including files reached through symlinks and files outside the root | Root confinement by realpath prefix check on every destination; refuse any symlink or non-regular file in a destination path; temp-and-rename writes; manifest written last; pointer files appended never replaced; `--force` restricted to `.ai/` conflicts (MIT-001, MIT-006, MIT-007, MIT-013) |
| Target repository to installer | Ownership decisions derived from hashes the installer computes itself | Pre-existing `.ai/**`, `.ai/manifest.yml`, `.ai/repository.yml`, `AGENTS.md`, `CLAUDE.md`, `.gitignore`, `docs/` layout, symlinks, FIFOs, huge files, any content a PR author could commit | `lstat` type checks; streaming SHA-256; manifest schema validation and scoping to the canonical set; unknown manifest entries ignored and never deleted; YAML loaded without aliases and size-capped; exact-line marker matching; uncommitted modifications never overwritten (MIT-004, MIT-005, MIT-009, MIT-010, MIT-014) |
| Process environment to installer | Parsed options and the resolved root | `--root`, `--force`, `--allow-non-git`, cwd, `PATH`, `GIT_DIR`, `GIT_WORK_TREE`, `GIT_CEILING_DIRECTORIES`, `HOME`, provider API keys | Root resolved with realpath, required to be a Git top-level containing a `.git` entry unless `--allow-non-git`, printed in the report and in `--dry-run`; option values beginning with `-` rejected; `/` refused and `$HOME` warned; API keys read once and used only as request headers (MIT-008, MIT-012) |
| Installer to provider APIs | Three constant HTTPS URIs, fixed headers, 5 s/10 s timeouts | Provider endpoints and any network intermediary | TLS via `Net::HTTP` with `use_ssl`; no redirects; response bodies parsed as JSON and treated as untrusted text; provider failures never fail `init`; control characters stripped before output (MIT-015, REQ-017) |
| Installer output to humans, agents, and upstream | Report lines, exit code, `.soft-foundry/runtime.yml`, the Soft Foundry-side diagnostic | The terminal, CI logs, agents reading the output, and the public upstream issue tracker the maintainer is directed to | Report is word-status plus root-relative path; diagnostic contains component, exception class and message, and root-relative or gem-relative paths only; never `ENV`, request headers, object `inspect`, absolute paths, or hostnames; target-side conditions are never labeled Soft Foundry-side (MIT-012, MIT-016) |
| Installed control plane to future agents | Files `init` wrote and hashed into the manifest | Everything an agent will read in the repository afterwards, including user-owned `AGENTS.md` prose, `skipped` conflicts, and `repository.yml` overrides | `init` never commits; every file has a status a reviewer can act on; `check` runs as a post-condition; marker blocks are verbatim and detectable; `check` warns on emptied path groups (proposed) (MIT-003, MIT-009, MIT-010) |
