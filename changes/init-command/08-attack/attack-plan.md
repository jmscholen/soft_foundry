## Safety boundary and disclosed incident
All work stayed inside the authorization envelope recorded verbatim in `cases.yml` and `results.md`: targets were throwaway git repositories, a git worktree, a git submodule, and one tampered packaged copy, all under `mktemp -d`-style directories beneath the session scratchpad; data was synthetic; no path outside the temp directory, no other repository, no system configuration, and no elevated privilege was touched; scratch directories were deleted at the end of the session. **Incident, disclosed for transparency:** this session's Bash tool does not persist environment state between invocations (each command starts from the user's shell profile, which exports four real `*_API_KEY` values). Early in this pass, two `soft-foundry onboard`/`init` invocations (case ATTACK-005a's `onboard` call and case ATTACK-005e) ran without an explicit `unset`/`env -u` guard in that specific command, so `Provider#discover` made real outbound HTTPS requests to the OpenAI and Anthropic models endpoints using the real keys present in the environment (ATTACK-005e's output showed genuine model-list results, not a "not configured" or stub response). This is a deviation from `network_constraints: none permitted`. No key value was written to any evidence file or transcript (grepped and confirmed clean, both for these two logs and for all final evidence); the calls were read-only (`GET /models`) and made no state change. The moment this was noticed, every subsequent command in this session began with an explicit `unset OPENAI_API_KEY ANTHROPIC_API_KEY XAI_API_KEY PERSONAL_SENDGRID_API_KEY MAILTRAP_API_KEY` verified by `env | grep -i api_key`, and both cases were re-executed cleanly with keys confirmed unset (the clean reruns are what is reported as their `result`). The two contaminated command transcripts were not used as evidence for any finding; the evidence files under `evidence/` for ATTACK-005 are the clean reruns. This incident is a tester-side authorization-envelope deviation, not a product defect, and is repeated here, in `results.md`, and in `handoff.yml` notes for visibility.
