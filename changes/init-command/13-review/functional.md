# Functional Review

## Scope reviewed
`soft-foundry init` and the code it depends on: `lib/soft_foundry/installer.rb`, `lib/soft_foundry/installer/source.rb`, `lib/soft_foundry/manifest.rb`, `lib/soft_foundry/agent_files.rb`, `lib/soft_foundry/safe_write.rb`, `lib/soft_foundry/git.rb`, `lib/soft_foundry/onboarding.rb`, `lib/soft_foundry/provider.rb`, `lib/soft_foundry/cli.rb#init`, `lib/soft_foundry/check.rb`, `lib/soft_foundry/control_plane.rb`, `lib/soft_foundry/errors.rb`, `exe/soft-foundry`, `soft_foundry.gemspec`, and `test/` (90 runs / 805 assertions, rerun independently at HEAD and confirmed green). Reviewed against the 17 locked requirements in `02-specification/requirements.yml` and the 17 locked acceptance criteria in `02-specification/acceptance-criteria.yml`, independently, not by re-reading verification's conclusions as authoritative.

## Independent verification performed
- Reran the full regression suite at HEAD `eaaf2e1`: `ruby -Ilib -Itest -e 'Dir.glob("test/**/*_test.rb").each { |f| require File.expand_path(f) }'` → 90 runs, 805 assertions, 0 failures, 0 errors, 0 skips. Matches `06-verification` and `08-attack` claims.
- Traced each requirement to code, not just to a passing test name:
  - REQ-001/AC-002: `CLI#resolve_root` refuses a non-Git target without `--allow-non-git`, uses `Git#toplevel` and `File.realpath` to confirm `--root` names the actual top-level. Confirmed in code.
  - REQ-002/AC-001: `Installer#adapter_actions` + `Installer::Source#entries` install `.gitignore`, `AGENTS.md`/`CLAUDE.md` markers, and the packaged `.ai/**` set. Confirmed.
  - REQ-003/AC-010: `Installer::Source#entries` substitutes `.ai/templates/repository.yml` for `.ai/repository.yml` and filters `.ai/harness-evals/**` to only `README.md` (`entry_for`, `EXCLUDED`, the `.ai/harness-evals/` `start_with?` guard). Diffed `.ai/templates/repository.yml` byte-for-byte against the pre-discovery `.ai/repository.yml` (commit `5a84acd`): identical except one clarifying word in a comment (`(unassessed template)`); `assessed: false`, `capabilities: {}`, confirming the template is genuinely unassessed, not a leak of this repository's own evidence. Confirmed.
  - REQ-004/REQ-010: `Installer#apply` writes managed files first, the manifest last (`apply` writes `written` array before computing/writing `plan.manifest.to_yaml`); a raised `TargetError` during `write` reports `files already written` so a partial install is diagnosable. Confirmed.
  - REQ-005/REQ-006/AC-003/AC-006/AC-007/AC-008: `Installer#entry_action`'s five-way `case` (`created`/`skipped: identical`/`conflict: uncommitted modifications`/`updated: owned by manifest`/`conflict or forced: differs from manifest or not in manifest`) is an exhaustive, mutually exclusive classification; every branch returns exactly one status. Confirmed by reading the method, not only by the test names.
  - REQ-007/AC-004/AC-005: `AgentFiles#plan_file` never rewrites body outside the marker block; a marker-without-block is `conflict`; legacy `CLAUDE.md` text is recognized as `skipped`. Confirmed, and the self-hosted `AGENTS.md` now carries exactly this marker pair with no other diff (verified via `git diff cc348f9..HEAD -- AGENTS.md`, two added lines only).
  - REQ-008/AC-011: `entry_action`'s `:scaffold` branch skips `docs/user/README.md` when `docs/` exists without `docs/user/`. Confirmed.
  - REQ-009/AC-012: `--dry-run` short-circuits before `installer.apply`; the report lines are printed identically for dry and real runs since both come from the same `plan.actions`. Confirmed by code inspection (the print loop runs unconditionally; only `apply` is gated on `dry_run`).
  - REQ-011/REQ-012/AC-013: `InternalError` vs `TargetError` are mapped to exit 4 vs exit 1 in `CLI#run`'s rescue chain; `upstream_guidance` names the component, states the fault is upstream, prints the diagnostic, and gives a fork command. Confirmed. See Security review for the classification-boundary discussion (`plan.clean`) and ATTACK-F-N02 below.
  - REQ-013/AC-014: `guard_path!` and `SafeWrite` confine every write to `root`; independently traced (see Security review) rather than accepted from `08-attack`'s "denied" verdict alone.
  - REQ-014/AC-016: `init`'s own report lines (`created`, `updated`, `skipped`, `conflict`, `forced`, `check: ok`/`check: failed`, `conflicts:`, `summary:`) are plain ASCII words with no color codes and no required Unicode glyph. `doctor` and `check` (not `init`) do print `✓`/`✗`, but REQ-014's statement is scoped to "init is non-interactive and its output..." — `doctor`/`check` are separate commands and the glyph is always paired with descriptive text, so meaning is not glyph-dependent even there. Not a REQ-014 violation; noted as a minor stylistic inconsistency in `accessibility.md`.
  - REQ-015/AC-017: `soft_foundry.gemspec` declares `required_ruby_version = ">= 3.2"` and `spec.files` explicitly lists `changes/README.md`, `docs/user/README.md`, and `.ai/**/*` (which includes `.ai/templates/repository.yml`). Confirmed by reading the gemspec directly and cross-checking `06-verification`'s `gem-build.log` claim (soft_foundry 0.2.0, 190 files, required_ruby_version >= 3.2) is consistent with the gemspec source.
  - REQ-016: `CLI#doctor` reports `.ai/manifest.yml` presence as one of its checks. Confirmed. On this repository `doctor` currently exits 2 because this repository was deliberately not self-installed (`05-implementation/decisions.md`); that is an expected, disclosed state, not a functional defect.
  - REQ-017: `Provider#discover` and `Onboarding` are unchanged in mechanism from before this change; provider errors are caught per-provider and never propagate to fail `init` (`Onboarding.new(root, out: @out).run(providers_only: true) unless no_onboard` is not wrapped in a rescue because `Providers.all.map(&:discover)` itself never raises — each `Provider#discover` has its own `rescue StandardError` boundary). Confirmed.
