13:Every finding states the failure it prevents: the concrete input or state, and the wrong result it leads to. A finding that cannot name one is minor at most. Every finding above minor carries it in the handoff as `failure:`, whatever its severity word, and the gate's `findings explained` check fails without it. Findings that only ask for defensive additions are not blocking or major by default: extra validation, rescues, retries, or nil checks for states the code cannot reach. A reviewer who wants one anyway names the input that reaches the state. A reviewer will always find something; the point is the failures that would happen, not the code that could be more cautious.
