# Trust Boundaries

| Boundary | Inside | Outside | Controls crossing it |
| --- | --- | --- | --- |
| TB-1 Phase session → record on disk | The coding shell running one skill under the guard, with `SOFT_FOUNDRY_PHASE` set | `changes/<slug>/**` | Guard write sets in block mode (Edit/Write against the skill's `permissions.yml`; Bash against deny sets); the gate at seal time; `phase seal` refusing a phase other than the session's own (MIT-001) |
| TB-2 Record on disk → git history | The worktree | The commits a later gate, `ci`, `change close`, and reviewers read | `phase seal`: gate first, then explicit-path staging, then a commit that runs the pre-commit hook (`ci`); `predecessor complete` requiring `recorded_commit`; `commit lineage`; the specification lock |
| TB-3 Runner → sessions | `soft-foundry phase run` in the parent process, outside the guard | The fresh session's process and whatever it writes | `executed_by` stamped by the runner before and after; `mark_blocked!`; sealing only after the gate passes; parallel sealing in lifecycle order; `--env` values confined to the child environment and redacted from output |
| TB-4 Committer → everything | A person or process with write access to the repository and git | Every file and every commit | None technical. Detectability: commit history, `recorded_commit`, review, the session ledger. Every check this change adds is presence-based, so a committer can forge any record field; the gate makes the forgery a commit someone made |
| TB-5 Repository policy → machine-local override | `.ai/policies/enforcement.yml` (protected from every skill's write set) | `.soft-foundry/enforcement.yml`, `SOFT_FOUNDRY_GUARD` | The gate reads only the repository policy (REQ-014); the guard honours the override by design, and a record produced under an override still has to show `executed_by` to pass |
| TB-6 Gate → evidence files | `Gate` code | YAML files, manifests, evidence files, `final.md`, all written by sessions or committers | `YAML.safe_load` with Time and Date only; realpath containment for manifest paths; symlink refusal on the named files; bounded set of parsed files (required files and the manifest, never `evidence/*` content) |
| TB-7 CLI → terminal and `soft-foundry ui` | Check names and details built by the gate | A terminal, a CI log, and the browser page `ui` serves | `Display.safe` for control characters; the page's existing escaping of check details; details are built from paths, ids and parser messages, never from file bodies |
