# Implementation Decisions

Plan decisions D1 to D7 (`04-plan/implementation.md`) were followed as written. The rows below are the decisions the code forced beyond them.

| Decision | Alternatives considered | Reason | Consequence |
| --- | --- | --- | --- |
| `RecordFileError` subclasses `TargetError` | A new top-level error; returning nil from the loader | The CLI already rescues `Error` and exits 1 with the message; a symlinked record file is the target repository's fault, which is what exit 1 means | `change status`, `gate`, `summary` and `seal` all print one line and exit 1 on a symlinked `handoff.yml` or `metadata.yml`; the gate's `evaluate` turns it into a `handoff present` failure so `ci` shows it per phase |
| `predecessor complete` also skips the recorded requirement on a closed or released record | Applying it everywhere | Closed records on `main` predate sealing and some phases were committed in one commit with the next; re-gating them would fail `ci` on history for no live reason | REQ-007's rule is applied to the one tightened existing check as well as the seven new ones |
| The runner seals with an empty environment (`env: {}`) | Passing the parent's environment through | The runner is the authority over the phase it ran; a parent shell that happens to carry `SOFT_FOUNDRY_PHASE` (a phase session running `phase run review`, as this repository does) must not have the seal refused as "another session's phase" | MIT-001 binds the manual command only; the runner's own sealing is never refused by the marker |
| Parallel: `moved` (HEAD changed during the run) is measured before any sealing, and a moved HEAD prevents sealing | Measuring after sealing and subtracting the runner's own commits | The sessions were told not to commit; if HEAD moved, their evidence is bound to a commit that is no longer HEAD and sealing would bury that | A parallel run whose session committed exits `EXIT_TARGET` with nothing sealed, as before, now stated |
| `Git#commit!` commits with `--only -- <paths>` after `add -- <paths>` | `git commit -m` after `add` | A file someone staged earlier would otherwise ride the sealing commit; `--only` limits the commit to the named paths whatever the index holds (REQ-033) | The sealing commit contains exactly the phase directory, `metadata.yml`, and `budget.yml` when changed |
| A refused commit leaves the metadata advance in the worktree | Reverting metadata on failure | REQ-004: a rerun must complete the seal with no repair step; the advanced metadata is the correct state once the commit lands, and until it lands every later gate fails `predecessor complete` | AC-010 passes; the hook's refusal text is shown verbatim |
| `branch_resolved` is stamped before the gate runs inside `seal` | After the gate, before the commit | The gate must measure what will be committed; stamping after would commit a handoff the gate did not read | A gate failure leaves `branch_resolved` written in the uncommitted handoff, which is true and harmless |
| Acknowledging a failed check means its id appears in a `blocking` entry or in a finding's `id` or `summary` | A structured `acknowledges:` field on findings | No template change for the common case; the boundary (text mention, not causation) is stated in `CHECKS` and the threat model (THREAT-005) | ATTACK-016's "mentioned in passing" case passes, as accepted |
| An unlisted evidence file is a warning, not a failure | Failing on any unlisted file | Earlier records keep scripts beside their transcripts under `evidence/`; a warning names them without re-judging those records' practice | Review can ask for the listing; the gate does not refuse |
| The lineage tip is `Scope.tip_for(…, resolved:) || HEAD` | HEAD only | A stacked record gated from another branch is measured on its own branch's tip, the same tip `evidence current` uses (AC-024) | One notion of "the tip" for staleness and lineage |
| `Text.blank?` is one regular expression used by `discharged?`, `criteria_not_covered` reasons, and nothing else yet | Per-call-site tests | REQ-022 asks every surface to agree; one definition cannot disagree with itself | `change close`, `check`, `ci`, the page and the summary read a U+00A0 `discharged_at` as open |
| `HarnessEval.complete_phase!` rewrites results, evidence paths, the manifest and the Outcome section only when `fill: true` | Always | `fill: false` exists so a test can keep the placeholders and see `no placeholders` fail; rewriting structure there would change what that test exercises | `gate_test` keeps its meaning |
| `fresh session recorded` reads `ControlPlane#enforcement_mode`, a new reader of `.ai/policies/enforcement.yml` only | Calling `Guard.mode`, which consults the environment and the machine-local override first | REQ-014: the repository's policy decides what its records must show | AC-038 passes; the guard's own precedence is unchanged |
