## REV-001, in the form the transcript shows
`Scope.tip_for` returns the recorded branch's tip when that tip strictly descends from the evidence commit. A ref created at the phases-complete commit satisfies that. `branch_edit` compares the `git.branch` string with the string in the evidence commit, so creating the ref is not an edit. ATTACK-017, a ref created at the evidence commit itself, is denied: that tip does not strictly descend from the evidence commit, and the checked-out HEAD is the measure. ATTACK-014, editing `git.branch` after the evidence commit, is denied.

The maintainer's reason for accepting the remainder is in `direction.md`: three attempts moved the hole, and a fix that treats every branch behind HEAD as the worktree broke stacked changes. This judgment accepts that, with the owed mitigation named above. The README's first known limit describes this procedure and states that the author already controls the evidence the gate reads.
