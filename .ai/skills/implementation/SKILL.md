# Implementation
Implement the approved plan. You may build and locally exercise the system but may not create or alter verification, evaluation, attack, review, judgment, or hidden harness evidence. Record deviations and challenges rather than silently changing the specification.

For a feature, fix, or refactor, commit the failing test before the code that makes it pass, as `.ai/rules/testing.md` asks: the RED commit is verification's evidence that the test existed before the implementation, and its hash goes into `06-verification/tests.yml` as `red_commit`. Name the two commits so a reader can tell them apart.
