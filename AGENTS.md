# Agent Bootstrap Contract

<!-- soft-foundry:begin -->
This file is the only required vendor-facing entry point. Canonical instructions live under `.ai/`.

1. Read `.ai/README.md` and `.ai/workflow.yml` before making changes.
2. Identify the current Git branch/worktree. The change slug is the branch name without a `change/` prefix; its record is `changes/<slug>/`.
3. If the record does not exist, create it with `soft-foundry change new <slug>`; never hand-copy templates. The change is on the repository's default lifecycle track (`tracks:` in `.ai/workflow.yml`) unless `--track` names another: `gated` runs every phase in order; `iterative` starts with an exploring stage.
4. Read `changes/<slug>/metadata.yml` for `track`, `status`, and `current_phase`, then `soft-foundry change status` for gate state. While `status` is `exploring`, load the track's stage skill (`.ai/skills/exploration/`) instead of a phase skill: iterate with the person, deploy only to the development environment recorded in `.ai/repository.yml`, append each round to `changes/<slug>/exploration/iterations.yml`, keep `02-specification/` as a living draft, and produce no verification, evaluation, attack, review, or judgment evidence. When the person accepts the feature, run `soft-foundry change vet`; the specification is then locked at that commit and the phases from implementation onward apply exactly as on the gated track. `soft-foundry change reopen` is the only way back to exploring.
5. Classify task and risk using `.ai/policies/` and record them in `metadata.yml`. Set `surfaces.accessibility: true` when a person will perceive or operate the result (UI, CLI output, a document); `.ai/rules/accessibility.md` then applies. Set `surfaces.policy: true` when the change alters what the application collects, shares, retains, protects, or promises in its published privacy policy, security policy, or terms; `.ai/rules/policy-conformance.md` then applies, and a policy text change it finds owed parks the change at `status: awaiting_human` until a person records the decision under `human_decisions`.
6. Load only the current phase skill: its `skill.yml`, `SKILL.md`, `permissions.yml`, `requirements.yml`, `completion.yml`, and the phase directory's template-derived working files. Path groups such as `${APP}` and `${TESTS}` resolve through `.ai/paths.yml` and `.ai/repository.yml`.
7. Honor read/write/deny boundaries. A skill must not perform another skill's job to manufacture a passing outcome.
8. Never weaken requirements, alter another phase's evidence, inspect hidden harness benchmarks when denied, or redefine success because implementation failed.
9. When a phase is done, fill its `handoff.yml` (status, commit SHA, completed time, resolved model, outputs, findings) and run `soft-foundry gate <phase>`. Never write `executed_by`: `soft-foundry phase run <phase>` writes it when it runs a phase in a fresh session, and review and judgment completed without it are advised as having been performed by the session already open. A failing gate is fixed by redoing the work, never by editing evidence or the handoff. An `advisory:` block after the gate output does not fail the gate; it lists what a human must address before the change goes live, and stays in the record until it is.
10. Any implementation change invalidates downstream commit-bound evidence. Follow `transitions` in `.ai/workflow.yml`: remediation, observability code changes, blocking review findings, and a BLOCKED judgment all return to `verify`.
11. Never declare the change complete without a final judgment artifact.

Where the host is Claude Code or Codex, `soft-foundry hooks install --claude` or `--codex` installs a PreToolUse guard that checks every file and shell tool call against the active skill's `permissions.yml` (`.ai/policies/enforcement.yml` sets whether a violation is reported or refused). If the host platform cannot technically enforce a permission, or the guard cannot see it (Bash is checked against deny sets only), treat the declared restriction as mandatory policy and record the limitation in the phase handoff's `notes`.
